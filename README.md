# PatchPort

PatchPort is an offline command-line tool that packages an exact replacement of one
existing UTF-8 text file into a deterministic, versioned JSON bundle. It inspects,
checks, previews, and safely applies the bundle only when the working copy matches
the expected original SHA-256 hash. PatchPort is a new, original, AI-assisted
implementation with no third-party runtime dependencies and an MIT license.

## Install and commands

Requires Python 3.11+:

```bash
python -m venv .venv
```

```powershell
.venv\Scripts\Activate.ps1
python -m pip install .
```

```bash
patchport make examples/before.txt examples/after.txt --path docs/message.txt --output change.patch.json
patchport inspect change.patch.json
patchport inspect change.patch.json --format json
patchport check change.patch.json --root demo-worktree
patchport apply change.patch.json --root demo-worktree --dry-run
patchport apply change.patch.json --root demo-worktree
```

`python -m patchport` is equivalent. Check/apply also accept `--format json`.

## Bundle and byte behavior

A bundle contains only `schema_version`, canonical relative POSIX `path`, expected
`before_sha256`, replacement `after_sha256`, and complete `after_text`. Version is
integer `1`; hashes are 64 lowercase hex characters. The replacement hash must
equal the SHA-256 of `after_text` encoded as UTF-8. Unknown/duplicate fields,
incorrect types, malformed or inconsistent hashes, non-UTF-8 source files, and NUL
text are rejected.

PatchPort reads and hashes raw bytes, then explicitly decodes/encodes UTF-8. This
preserves Unicode, UTF-8 BOMs, CRLF, and final-newline presence. Bundles contain no
timestamp or absolute machine path. They do not contain original text, so inspection
reports metadata and cannot claim to show a before/after diff.

## Status and application

- `ready`: target hash equals the expected baseline.
- `already_applied`: target hash equals the replacement; apply succeeds without a rewrite.
- `conflict`: missing/non-file target or hash matching neither value; exit `1`.

Dry run creates no temporary file and changes nothing. When ready, it shows a unified
diff using the actual matching baseline and marks missing final newlines clearly.

Real apply writes and flushes a temporary file in the target directory, copies the
ordinary permission mode supported by the platform, rechecks the baseline, and uses
`os.replace`. Pre-replacement failures clean the temporary file. PatchPort assumes no
concurrent edit occurs between the final recheck and replacement. It does not promise
to preserve ownership, ACLs, extended attributes, timestamps, or platform metadata
beyond tested ordinary mode bits.

Paths must be canonical relative POSIX paths. Absolute, traversal, drive/UNC,
backslash, empty, `.git`, escaping, symlink-target, and symlink-parent paths are
rejected. Parent directories and regular target files must already exist. Version
0.1.0 replaces one existing file only.

Content hashes detect byte differences; they do **not** authenticate the bundle's
author. Use a trusted channel for provenance.

## Demo

The synthetic `examples/message.patch.json` was generated by PatchPort. Prepare a
temporary worktree:

```powershell
New-Item -ItemType Directory demo-worktree\docs -Force
Copy-Item examples\before.txt demo-worktree\docs\message.txt
patchport check examples\message.patch.json --root demo-worktree
patchport apply examples\message.patch.json --root demo-worktree --dry-run
patchport apply examples\message.patch.json --root demo-worktree
```

## Exit codes and tests

- `0`: make/inspect/ready/dry-run/applied/already-applied success.
- `1`: target conflict or unmet application precondition.
- `2`: invocation, malformed bundle, rejected path, unreadable input, or operation error.

```bash
python -m unittest discover -s tests -v
```

Tests cover deterministic bundles, Unicode/CRLF/BOM/newline edge cases, strict
validation, paths/symlinks, conflicts, permissions, concurrent baseline changes,
cleanup, and CLI behavior. Windows symlink coverage is skipped without the required
OS privilege.

Current limitations: one existing text file only; no creation/deletion/rename,
multi-file transaction, receipt/restore system, signature, or general unified-diff
import. Proposed work is in [ROADMAP.md](ROADMAP.md).
